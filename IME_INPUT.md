# Native Chinese composition

Editable text uses shared `ImeInput` / `ImeTextarea` controls. The native DOM owns preedit text; compositionstart, compositionupdate and composing input events mark the field active without publishing every Pinyin edit to React. Compositionend publishes the browser's value, and a subsequent final input event can update it if Safari delivers that event later. No transliteration, normalization, selection replacement or forced conversion runs during composition.

External values (autocomplete, auto-meaning, reset) synchronize before layout only when the native field is not composing and its value actually differs. The same DOM node, native selection and browser candidate handling remain in place. Add pauses suggestion requests, adaptive sizing and selection-state updates while its English editor composes. Starting a Chinese meaning composition claims manual ownership before a late lookup can overwrite it. Deliberately cleared meanings remain manual.

Key handling leaves live IME Enter / arrow / space events to the browser. App shortcuts ignore isComposing, keyCode 229 and the short trailing Enter interval Safari can emit after compositionend. Form-level checks also reject submit requests while any field composes or is still in the 80ms commit interval. Explicit saving after the commit interval uses the existing data model and error recovery. Dictionary reference responses do not scroll away from a focused text editor, and navigation / dismissal guards cover all composing fields in the sheet. Busy meaning saves use read-only input rather than disabling it. Existing field borders use one contiguous focus treatment; the Add title retains its single focused divider.

Coverage includes Dictionary My meaning, Add English / meaning / My Context, Library word / meaning / example / search, related-word inline meaning and authentication text fields. File inputs and checkboxes retain their native handling. No database or Storage migration is required.

Scripted tests model Pinyin preedit, composition updates, final Chinese commits, late responses, an input event arriving after compositionend, editing inside existing Chinese, switching back to English, stable DOM identity/value setters/caret, multiline Expressions and preventing premature writes. Synthetic browser events cannot open or validate the real iOS candidate keyboard. Physical iPhone Safari and installed-PWA candidate selection, keyboard switching and dictation remain unverified and require device testing. Browser save tests use isolated Supabase fixtures and never mutate personal production entries.

Release validation: build, lint and typecheck passed; all 100 unit tests passed. The nine IME scenarios passed in Chromium and iPhone WebKit. Full Chromium regression passed 230 cases with five expected account/configuration skips and one video-setup click timeout; the final 37-case IME/adaptive/video rerun passed, including that case. The iPhone run passed 47 cases with two platform skips and one edit-fill timeout; the complete Dictionary file rerun passed all five applicable cases (one Chromium-only skip), including failure/retry. These two timeouts were not reproduced on independent runs. No failed functional case remains unresolved. Physical iPhone candidate/PWA testing remains unverified.
